# 01. 정보구조 (IA)

> JAPAN FINDS — 일본 한정상품 발견 플랫폼. 판매·구매대행을 하지 않는다.
> 목적 흐름: **상품 발견 → 상품 정보 확인 → 구매 의향 형성 → 겸사겸사 부탁 전환**

## 1. 사이트맵

```
/                         홈 (큐레이션 섹션 6개)
├─ /products              상품 목록 · 검색 · 필터
│   └─ /products/[slug]   상품 상세 (전환이 일어나는 화면)
├─ /category/[slug]       카테고리 랜딩 (8종)
├─ /brand/[slug]          브랜드 허브 (상품 + 일정)
├─ /schedule              일정·소식 (발매 · 팝업 · 캠페인 · 예약 · 추첨 · 재입고)
├─ /compare               일본·한국 가격 비교 (동일 상품 검증된 것만)
├─ /saved                 관심 상품 (localStorage → 추후 Supabase Auth)
├─ /admin                 관리자 (비공개)
│   ├─ 후보 검수          수집 후보 · AI 결과 검토 · 승인/반려/병합
│   ├─ 게시 상품          수정 · 판매 종료 처리
│   └─ 수집 로그          자동 수집 실행 내역
├─ /sitemap.xml           게시 상품 · 카테고리 · 브랜드 URL
└─ /robots.txt            /admin 차단

(외부) 겸사겸사 부탁 작성 화면 ← 상품 상세의 CTA에서만 이동
```

카테고리 슬러그(`src/lib/types.ts`의 `CategorySlug`):

|---|---|
| character | 캐릭터·애니메이션 굿즈 |
| gacha | 가챠·피규어 |
| fashion | 패션·액세서리 |
| beauty | 뷰티·화장품 |
| stationery | 문구·잡화 |
| living | 생활용품 |
| regional | 일본 지역 한정상품 |
| popup | 팝업스토어 한정상품 |

## 2. 화면별 정의

| 화면 | 목적 | 핵심 요소 | 주 진입 경로 |
|---|---|---|---|
| 홈 `/` | 발견의 재미. 가입·겸사겸사 홍보 없이 바로 탐색 | 메인 배너 + 큰 검색창, **카테고리 아이콘 섹션**, 섹션 6개(지금 주목할 한정템 · 최근 출시 신상품 · 캐릭터·가챠 · 팝업스토어 한정 · 곧 출시 · 가격 비교), **다가오는 일정** | 직접 방문, 브랜드 검색 |
| 목록 `/products` | 조건에 맞는 상품 좁히기 | 검색창, 필터(카테고리·한정 유형·지역·한국 공식 판매·가격대), 정렬, 카드 그리드(모바일 2열 / 데스크톱 4~5열) | 홈 섹션 '전체 보기', 헤더 검색, 탭바 '탐색' |
| 상세 `/products/[slug]` | 정보 신뢰 확보 → 구매 의향 → 부탁 전환 | 이미지, 한·일 상품명, 한정 여부와 근거, 일본 가격·예상 원화, 한국 가격·차이, 출시·종료일, 판매처, 구매 조건, 공식 출처·확인 시각, 관련 상품, 저장, 구매 부탁 CTA | **검색엔진 유입(시나리오 A의 시작점)**, 카드 클릭 |
| 카테고리 `/category/[slug]` | SEO 랜딩 + 카테고리 탐색 | 카테고리 소개 한 줄, 해당 상품 그리드, 목록 필터로 이어지는 링크 | 검색엔진, 홈 카테고리 메뉴 |
| 브랜드 `/brand/[slug]` | SEO 랜딩 + 브랜드 허브 | 브랜드명, 해당 상품 그리드, **그 브랜드의 일정·소식** | 검색엔진, 상세의 브랜드 링크 |
| 일정·소식 `/schedule` | 발매·팝업·마감을 놓치지 않게, 재방문 이유 | 상태 탭(진행 중·예정·종료), 종류 칩, 일정 카드(기준일·D-day·한국 이용 범위·근거 표시), 원제, 공지 확인·링크 확인 시각, 변경 내역, 관련 상품 | 탭바 '일정', 홈 '다가오는 일정', 상세의 관련 일정 |
| 가격 비교 `/compare` | "일본에서 사면 얼마나 다른가" 확인 | 상품별 일본가·한국가 비교 막대, 차이, 확인 시각, 미포함 비용 안내 | 탭바, 홈 6번 섹션 |
| 관심 상품 `/saved` | 쇼핑리스트 보관, 재방문 이유 | 저장한 상품 카드, 빈 상태 안내 | 헤더 하트, 탭바 |
| 관리자 `/admin` | AI 결과를 사람이 확인한 뒤에만 게시 | 후보 목록·AI 필드별 신뢰도·중복 의심·이미지 사용권·승인 버튼, 게시 상품 관리, 수집 로그 | 주소 직접 입력(메뉴에 노출하지 않음) |

## 3. 내비게이션 규칙

| 영역 | 규칙 |
|---|---|
| 상단 헤더 (공통) | 로고(홈) · 검색 · 관심 상품(하트). 데스크톱은 카테고리 메뉴를 헤더 아래 한 줄로 노출 |
| 하단 탭바 (모바일) | 5개: 홈 · 탐색(`/products`) · 일정(`/schedule`) · 가격비교(`/compare`) · 관심(`/saved`) |
| 상세 화면 | 탭바를 숨기고 **고정 CTA**(저장 + "일본 여행자에게 구매 부탁하기")로 대체 |
| 겸사겸사 노출 | 홈·목록에는 광고성 노출 없음. 구매 의도가 생기는 상세 화면에서만 연결 |
| 관리자 | 헤더·탭바·푸터·사이트맵 어디에도 링크하지 않음 |
| 뒤로 가기 | 목록 필터·검색어는 쿼리스트링에 두어 뒤로 가기·공유 시 그대로 복원 |

## 4. URL 규칙 (SEO)

| 항목 | 규칙 |
|---|---|
| 상품 | `/products/[slug]` — slug는 영문 소문자·숫자·하이픈. 게시 후 바꾸지 않는다(바꾸면 301) |
| 목록 쿼리 | `q`(검색어) · `category` · `limited`(japan/region/store/period/quantity) · `region` · `kr`(yes/no/unknown) · `price`(가격대) · `sort`(new/price_asc/price_desc, popular은 데이터 확보 후) |
| canonical | 필터가 붙은 `/products?…`는 canonical을 `/products`로. 카테고리·브랜드는 전용 경로가 canonical |
| 일정 | `/schedule` 한 화면에서 상태·종류를 쿼리(`status` · `kind`)로 거른다. 일정별 고유 주소(`/schedule/[slug]`)는 일정 수가 늘어 검색 유입이 필요해지면 추가한다(후속) |
| 색인 대상 | 홈, 상세, 카테고리, 브랜드, 일정·소식, 가격 비교 |
| 색인 제외 | `/admin`(robots 차단 + noindex + 인증), `/saved`(개인 상태, noindex), 검색 결과 쿼리 페이지 |
| 메타 | 상세: `<한국어 상품명> – 일본 한정 여부·가격·판매처 | JAPAN FINDS` 형태의 제목, 한정 근거·가격·판매처를 담은 설명, OG 이미지 |
| 구조화 데이터 | 상세에 `Product` + `Offer`(가격·통화·판매처), 목록·카테고리에 `BreadcrumbList`. 확인되지 않은 가격은 넣지 않는다 |
| sitemap | 게시(`published`) 상태 상품만. 판매 종료 상품은 페이지를 유지하되 '판매 종료' 표시 |
| 데모 데이터 | 예시 상품(`isDemo: true`)만 있는 동안에는 운영 도메인에 색인시키지 않는다 |

> `/schedule`의 일정별 상세 주소와 프로토타입의 실제 쿼리 이름은 구현(`src/app/schedule`)과 맞춰 확정한다. 일정·소식을 넣게 된 배경은 [`07_덕비서_벤치마크.md`](07_덕비서_벤치마크.md).

## 5. 겸사겸사 연결 지점

| 조건 | 상세 화면 CTA |
|---|---|
| `NEXT_PUBLIC_GYEOMSA_REQUEST_URL` 설정됨 | "일본 여행자에게 구매 부탁하기" → 상품 id·이름·브랜드·판매처·공식 URL·ref를 쿼리로 넘겨 이동 |
| 설정 안 됨 | "구매 부탁 출시 알림 받기" (알림 신청 수집) |

실제 서비스 주소는 코드에 넣지 않는다. 전달하는 값은 관리자가 검증한 상품정보뿐이고 개인정보는 넘기지 않는다.
