# 05. 자동수집 아키텍처 (소스별 수집 가능 여부 확인 + 파이프라인 설계)

- 확인일: 2026-11-13 (모든 URL은 이 날짜에 직접 요청해 본 결과)
- 상태: 설계 문서. 수집기는 아직 구현하지 않음.
- 원칙: 무조건 크롤링하지 않는다. 공식 API · RSS · 이용약관 · robots.txt로 허용이 확인된 경로만 쓴다. 이미지 · 본문 전체를 복제하지 않는다. 허용되지 않는 사이트는 "URL 등록 + 관리자 수동 검증"으로 처리한다.

## 읽기 전에: 확인 방법과 한계

- robots.txt와 RSS는 curl로 원문을 직접 받았다(이 문서의 인용은 원문 그대로).
- 이용약관 · API 문서는 페이지를 받아 요약 도구로 해당 조항을 뽑았다. 조항 번호와 인용문은 그 결과이므로, **계약 · 법률 판단에 쓰기 전에 원문 페이지를 사람이 한 번 더 대조**해야 한다.
- 소스당 요청은 3~6회로 제한했다. 403/429/503이 나온 곳은 우회하지 않고 "확인 못함"으로 적었다.
- 로그인 · 계정 생성 · 약관 동의는 하지 않았다. 따라서 API 키 발급 화면에서만 보이는 조건은 전부 "확인 필요"다.
- 표기: **[확인]** = 이번에 직접 본 사실 / **[추정]** = 직접 보지 못해 추정 / **[확인 필요]** = 구현 전 반드시 확인.

## 2. 소스별 상세

### 2.1 PR TIMES

**[확인] robots.txt 원문** (`https://prtimes.jp/robots.txt`, HTTP 200)

```
User-agent: *
Allow: /
Disallow: /api/press_release.php/press_release/*/like_count
Disallow: /im/action.php?run=html&page=releaseimage
Disallow: /upload/*.m3u8

sitemap: https://prtimes.jp/sitemap.xml
sitemap: https://prtimes.jp/sitemap-news.xml
```

**[확인] RSS**
- 전체 피드: `https://prtimes.jp/index.rdf` — HTTP 200, `application/xml`, RSS 1.0(RDF). 받은 시점에 항목 200건. 채널 설명은 "PR TIMES - RSS Release Feed.", 권리 표기는 `Copyright (c) PR TIMES Inc. All Rights Reserved.`
- 항목 필드: `title`, `link`, `description`, `dc:corp`(기업명), `dc:date`. 항목 하나가 약 560자 수준이라 **본문 전문은 들어 있지 않다.**
- 기업별 피드: `https://prtimes.jp/companyrdf.php?company_id={기업ID}` — `company_id=112`로 HTTP 200, 같은 RDF 형식 확인.
- 키워드 페이지(`/topics/keywords/限定商品`)의 `<link rel="alternate">`는 전체 피드(`index.rdf`)만 가리킨다. **키워드 전용 피드는 발견하지 못했다.**

**[확인] 이용약관** (`https://prtimes.jp/main/html/kiyaku`, 요약 도구 추출)
- 자동 수집 · 스크레이핑을 직접 금지하는 조항은 없음. 관련될 수 있는 조항: 기본규약 제15조(19) 서비스의 소프트웨어 · 데이터 복제 · 개변 · 2차 이용 금지, 제15조(20) 부정 접근 · 대량 패킷 송신 금지.
- 기본규약 제14조 1항: 기업 콘텐츠의 저작권은 게시한 기업(또는 그 라이선서)에 귀속.
- 일반규약 제3조 1항 · 제6조 1항(1): 일반 이용자는 정보 열람과 저작권법상 "사적 사용을 위한 복제" · "인용" 범위에서만 기업 콘텐츠를 무상 이용. 그 밖의 이용은 금지.
- 보도규약 제3조 1항: 미디어 유저 · 보도 관계자는 **보도 목적에 한해** 기업 콘텐츠를 무상 이용 가능.
- RSS에 관한 규정, 외부 제공용 데이터 API에 관한 규정은 약관에서 찾지 못함.

**[추정]**
- 카테고리별 피드 존재 여부(직접 요청해 보지 않음).
- JAPAN FINDS가 "미디어 유저/보도 관계자"에 해당해 보도 목적 이용(이미지 포함)을 인정받을 수 있는지 — 미디어 등록 심사가 있을 것으로 보이나 확인하지 않음.

**[확인 필요]**
- 카테고리 · 키워드 피드 유무(PR TIMES 문의 또는 헬프 확인).
- 미디어 유저 등록 조건과, 등록 시 이미지 · 본문 이용 범위.
- 기사 상세 페이지(HTML)를 LLM 분석용으로 한 번 읽는 것이 약관 제15조(19)에 저촉되는지. **결정 전까지 MVP는 RSS의 title/description만 LLM에 넣는다.**
- 피드 갱신 주기와 권장 폴링 간격(명시된 것을 찾지 못함).

**수집 설계**
- 전체 피드를 폴링한 뒤 키워드(限定, 新商品, 数量限定, 先行販売, コラボ 등)와 관심 기업 목록으로 수집기 쪽에서 걸러낸다.
- 관심 브랜드는 기업별 피드를 직접 구독한다. 포켓몬 · 반다이처럼 공식 스토어를 자동 수집할 수 없는 브랜드는 **해당 기업의 PR TIMES 피드가 대체 경로**가 된다(각 기업의 company_id는 확인 필요).

### 2.2 포켓몬센터 온라인

**[확인] robots.txt 원문** (`https://www.pokemoncenter-online.com/robots.txt`, HTTP 200)

```
# All spiders are allowed to access all static resources
User-agent: *
Disallow: 
```

**[확인] 이용약관** (`https://www.pokemoncenter-online.com/terms.html`, 최종 갱신일 2026년 02월 13일, 요약 도구 추출)
- 제6조 ⑰: "自動化された手段（自動購入ツール、BOTなどこれらに準ずる手段）を用いて本サービスを利用する行為（在庫情報等の取得行為を含む）" 금지.
- 제6조 ⑱: 크롤링(크롤러 · 로봇 · 스파이더 등), 스크레이핑 및 유사 수단으로 서비스에 접근하거나 서비스 관련 정보를 취득하는 행위 금지.
- 제5조(지식재산권): 콘텐츠는 이용자가 개인적으로 즐기는 경우에 한해 이용 허락. 제6조 ④ 저작권 침해 금지, ⑥ 사이트 데이터의 개변 · 수정 · 번안 금지.

**판정**: robots.txt는 전부 허용이지만 약관이 명시적으로 금지하므로 **자동 수집하지 않는다.** 관리자가 상품 URL을 등록하고 내용을 직접 확인해 입력한다.

**[확인 못함]**
- 공식 RSS/피드 존재 여부(이번에 확인하지 않음. `/guide/rule.html`은 404).
- 공식 API: 찾지 못함. 공개 API가 없다고 단정할 근거도 없음 → 확인 필요.

### 2.3 치이카와 마켓

**[확인] Shopify 기반** — robots.txt 첫 줄이 "# Shopify storefront. …"이고, 약관 · 연락처로 Shopify를 안내하며, 상품 이미지가 `cdn.shopify.com`에서 제공된다.

**[확인] robots.txt 요지** (`https://chiikawamarket.jp/robots.txt`, HTTP 200. 전문이 길어 핵심만 옮김)

```
User-agent: *
Allow: /
Disallow: /admin
Disallow: /cart/
Disallow: /checkout
Disallow: /checkouts/
Disallow: /orders
Disallow: /account
Disallow: /services
Disallow: /cart.js
Disallow: /recommendations/products
Disallow: /collections/*sort_by*
Disallow: /collections/*filter*&*filter*
Sitemap: https://chiikawamarket.jp/sitemap.xml
```

- 상품(`/products/`) · 컬렉션(`/collections/`) 경로는 robots상 허용. `/products.json`은 Disallow 목록에 없음.
- 파일 머리말 주석에 AI 에이전트용 안내(UCP/MCP 엔드포인트, `agents.md`)가 있다. `agents.md`의 "Read-only browsing"에는 `GET /collections/all`, `GET /products/{handle}.json`, 사이트맵이 적혀 있다.

**[확인] 공개 피드**
- `https://chiikawamarket.jp/products.json?limit=1` → HTTP 200, JSON. 필드: `id`, `title`, `handle`, `body_html`, `published_at`, `created_at`, `updated_at`, `vendor`, `product_type`, `tags`, `variants[]`(`sku`, `price`, `available` 등), `images[]`(`src`, `width`, `height`).
- 확인한 상품 1건에서 `handle`과 `sku`가 13자리 숫자(`4595430855673`)였다. JAN으로 보이지만 1건만 본 것이라 **[추정]**.
- `https://chiikawamarket.jp/collections/all.atom` → **HTTP 429 `local_rate_limited`** (몇 초 사이 네 번째 요청). Atom 피드 존재 여부는 확인 못함. 요청 빈도에 민감하다는 점은 확인.

**[확인] 이용약관** (`https://chiikawamarket.jp/policies/terms-of-service`, 조 번호 없이 【】 표제로 구분, 요약 도구 추출)
- 【禁止事項】: "当社の事前の許可を得ることなく、自動化された手段（自動購入ツール・ロボットなどこれらに準ずる手段）を用いて商品を購入その他本サイトを利用する行為（商品ページ上の情報取得等を含む）"
- 【禁止事項】: 서버에 과도한 부담을 주는 행위 금지.
- 【著作権等について】: 사이트 내용의 지식재산권은 운영사 또는 허락한 제3자에 귀속. 사적 이용 목적을 넘는 복제 · 배포 · 판매 · 공표 금지.

**판정**: 기술적으로는 열려 있지만(robots 허용, 공개 JSON, agents.md) **약관이 사전 허가 없는 자동 정보 취득을 금지**한다. 두 신호가 엇갈릴 때는 더 엄격한 쪽(약관)을 따른다 → **수동 URL 등록.** 운영사(株式会社グレイ・パーカー・サービス)의 서면 허가를 받으면 Shopify 공개 JSON 어댑터로 전환할 수 있다.

**[확인 필요]**
- 운영사에 자동 수집(상품 메타데이터만, 낮은 빈도) 허가 문의.
- `agents.md`의 "Read-only browsing"이 약관상 "사전 허가"에 해당하는지에 대한 운영사 해석.
- `agents.md` 나머지 부분과 UCP/MCP 엔드포인트의 이용 조건(이번에는 앞부분만 읽음).

### 2.4 반다이 가샤폰

**[확인] robots.txt** — `https://www.gashapon.jp/robots.txt`, `https://gashapon.jp/robots.txt` 모두 **HTTP 404** ("403 Forbidden/404 Not Found" 안내 HTML 반환). robots.txt 파일이 없다. 파일이 없다는 것은 허용을 뜻하지 않으며, 아래 이용 조건이 우선한다.

**[확인] 사이트 이용 조건** (`https://gashapon.jp/news/info_260603/`, 요약 도구 추출)
- "自動化された手段（自動ツール・プログラム・ロボットなどこれらに準ずる手段）を用いて掲載情報を取得/使用することはバンダイの事前許諾がない限り、禁止いたします。"
- "本サイトに掲載されている全ての画像、文章、データの無断転用、転載をお断りします。" 이어서 AI 등을 이용한 2차 이용도 같은 방식으로 금지한다고 명시.
- 사적 사용 등 법령이 인정하는 범위를 넘는 게재 정보의 사용(복제 · 개변 · 게시 · 배포 등)은 사전 허락 없이는 금지.
- 자동 데이터 수집으로 서버 다운 등 손해가 생기면 배상 책임을 진다는 취지의 문구 있음.
- 게재 정보의 저작권은 반다이 또는 권리자에 귀속.

**[확인] 기타**
- 발매 스케줄 페이지: `https://gashapon.jp/schedule/`, 뉴스: `https://gashapon.jp/news/` (메인 페이지 링크로 확인).
- 상품 이미지 투고 안내(`/news/info_260807/`)는 공식 상품으로 오인될 투고를 삼가 달라는 내용이며, 미디어 · 상업 사이트의 상품 이미지 사용 가부는 적혀 있지 않다.

**판정**: 자동 수집 금지 + AI 2차 이용 금지가 모두 명시돼 있다 → **수동 URL 등록.** 이 소스는 관리자가 직접 읽고 사실 정보(상품명 · 가격 · 발매월)만 자기 문장으로 입력하며, **사이트 본문을 LLM에 넣지 않는다.**

**[확인 못함]**
- RSS/피드: 메인 페이지에서 받은 범위에는 피드 링크가 없었으나 `<head>`를 확인하지 못함.
- 공식 API: 찾지 못함.
- 반다이 · BANDAI SPIRITS의 생성 AI 관련 별도 공지 내용.

### 2.5 라쿠텐 웹서비스 (Ichiba Item Search API)

**[확인 못함] — 이번 조사에서 공식 사이트 전체가 HTTP 503**
- `https://webservice.rakuten.co.jp/robots.txt` → 503
- `https://webservice.rakuten.co.jp/documentation/ichiba-item-search` → 503
- `https://webservice.rakuten.co.jp/guide/rule` → 503
- `https://webservice.rakuten.co.jp/` (간격을 두고 1회 재시도) → 503

**따라서 다음은 모두 "확인 필요"** — 엔드포인트와 버전, 필수 파라미터, 신청 조건, 호출 한도, 출처(크레딧) 표기 의무, 응답 필드(JAN 포함 여부), 취득 데이터 보관 · 이미지 사용 조건, 상업 이용 조건.

**[추정] 제3자 자료에서 본 내용 (공식 확인 아님, 사실로 쓰지 말 것)**
- 개인 블로그(Qiita)에, 기존 `app.rakuten.co.jp` 계열 API가 2026-05에 종료되고 `openapi.rakuten.co.jp` 계열로 이전됐으며 새 인증에 accessKey와 Referer 헤더가 필요하다는 글이 있다.
- 제3자 도구 설명에, 응답 레코드에 "Supported by Rakuten Developers" 크레딧을 붙인다는 언급과 검색 결과 상한(page × 30 ≤ 3,000건) 언급이 있다.
- 다른 라쿠텐 API(태그 검색) 문서의 검색 요약에, 짧은 시간에 같은 URL로 대량 접근하면 일정 시간 이용이 제한될 수 있다는 문구가 있다.

**판정**: 방식은 공식 API가 맞을 것으로 보지만 **조건을 하나도 확인하지 못했으므로 MVP에서 보류.** 공식 문서 · 규약을 사람이 직접 확인한 뒤 어댑터를 추가한다.

### 2.6 Yahoo! 쇼핑 API (商品検索 v3)

**[확인] 크레딧 표시 의무** (`https://developer.yahoo.co.jp/attribution/`)

**[확인 못함] / [확인 필요]**
- **상업 이용 조건**: "WebAPIの商用利用について" 페이지를 `developer.yahoo.co.jp/appendix/commercial/`로 요청했으나 404(주소를 추측한 것이라 페이지가 없다는 뜻은 아님). 제2장 3(3)이 금지 조항인지 조건부 조항인지 원문 대조 필요. JAPAN FINDS가 광고 · 제휴 수익을 붙일 계획이면 출시 전 반드시 확인.

**수집 설계**: 키워드(限定, 新発売 등) · 브랜드 · JAN 조회에 쓴다. 한정판 "발견" 소스라기보다 **PR TIMES에서 찾은 상품의 가격 · JAN · 판매처를 보강하는 용도**가 적합하다.

## 3. 수집 파이프라인 설계

### 3.1 전체 흐름

```
 [GitHub Actions 스케줄 / 수동 실행]
              |
              v
 +---------------------------- Python 수집기 ----------------------------+
 |  SourceAdapter (소스별)                                               |
 |   - PrTimesRssAdapter      : index.rdf + 기업별 피드                  |
 |   - YahooShoppingAdapter   : itemSearch v3 (appid, 1 req/s)           |
 |   - ManualUrlAdapter       : 관리자가 등록한 URL (네트워크 수집 없음) |
 |   - (보류) RakutenAdapter  : 공식 조건 확인 후 추가                   |
 |                                                                       |
 |  fetch -> normalize -> dedupe(url_hash, JAN) -> upsert                |
 +-----------------------------------------------------------------------+
              |                                   |
              v                                   v
     product_candidates (status=collected)   collection_logs
              |
              v
     LLM 분석 워커 (한국어 정리 · 필드 추출 · 중복 판별)
              |
              v
     product_candidates (status=analyzed, llm_result JSON)
              |
              v
     관리자 검수 화면 (승인 / 수정 후 승인 / 반려 / 병합)
              |
              v
     products (게시)  ---->  사용자 화면
```

### 3.2 어댑터 인터페이스 (초안)

```python
class SourceAdapter(Protocol):
    source_id: str            # "prtimes_rss", "yahoo_shopping", "manual_url"
    min_interval_sec: float   # 요청 간 최소 간격
    def fetch(self, since: datetime) -> Iterable[RawItem]: ...
    def normalize(self, raw: RawItem) -> Candidate: ...
```

- 어댑터는 "허용이 확인된 경로"만 구현한다. 새 소스를 추가할 때는 이 문서의 판정 표에 근거 URL과 확인일을 먼저 적는다.
- `ManualUrlAdapter`는 네트워크 요청을 하지 않는다. 관리자가 입력한 URL과 수기 필드를 candidate로 넣기만 한다.

### 3.3 테이블 (초안)

**product_candidates**

| 컬럼 | 설명 |
|---|---|
| id | PK |
| source_id | 어댑터 ID |
| source_url | 원문 URL (정규화 후) |
| source_url_hash | 중복 제거 키 1 |
| jan_code | 중복 제거 키 2 (있을 때) |
| raw_title, raw_summary | 소스가 제공한 제목 · 요약 (전문 저장 안 함) |
| raw_published_at | 소스 발행 시각 |
| raw_payload | API/RSS 원 항목 JSON (이미지 바이너리 없음, URL만) |
| llm_result | 4장의 JSON |
| llm_model, llm_prompt_version | 재현용 |
| status | collected / analyzed / needs_review / approved / rejected / merged |
| duplicate_of | 병합 대상 candidate 또는 product id |
| collected_at, analyzed_at, reviewed_at, reviewed_by | 이력 |

**collection_logs**

| 컬럼 | 설명 |
|---|---|
| id, run_id | 실행 단위 식별 |
| source_id | 어댑터 ID |
| started_at, finished_at | 실행 시간 |
| request_count | 실제 요청 수 |
| fetched_count, new_count, duplicate_count | 수집 결과 |
| http_status_summary | 예: `{"200": 3, "429": 1}` |
| retry_count | 재시도 횟수 |
| error_message | 실패 시 메시지 |
| outcome | success / partial / failed / skipped_blocked |

### 3.4 중복 제거

1. **출처 URL 해시**: URL 정규화(스킴 · 호스트 소문자, 추적 파라미터 `utm_*` 등 제거, 끝 슬래시 통일) 뒤 SHA-256. 같은 소스의 재수집을 막는다.
2. **JAN 코드**: 같은 상품이 여러 소스(PR TIMES 기사 + Yahoo! 쇼핑 판매 페이지)에서 들어온 경우를 묶는다. JAN이 일치하면 새 candidate를 만들지 않고 기존 건에 "판매처/출처"로 붙인다.
3. **LLM 유사 판별**: JAN이 없을 때 브랜드 + 정규화한 상품명 + 발매일로 후보를 좁히고, LLM이 `duplicate_candidates`에 근거와 함께 제안한다. **자동 병합하지 않고** 관리자가 결정한다.

### 3.5 스케줄 · 재시도 · 예절

**GitHub Actions (예시)**

```yaml
on:
  schedule:
    - cron: "17 */3 * * *"   # 3시간마다, 정각을 피함 (UTC)
  workflow_dispatch: {}
concurrency:
  group: collector
  cancel-in-progress: false
```

- 폴링 주기 3시간은 설계상 초기값이다. 소스가 요구한 값이 아니며, PR TIMES의 권장 간격은 확인하지 못했다.
- API 키(appid)는 GitHub Secrets에 둔다. 로그에 찍지 않는다.

**재시도 (지수 백오프)**
- 대상: 네트워크 오류, 5xx, 429.
- 대기: `base × 2^n + 지터`, base 2초, 최대 3회. `Retry-After` 헤더가 있으면 그 값을 우선한다.
- **403 또는 반복되는 429/503은 재시도를 멈추고** 그 소스를 해당 실행에서 건너뛴다(`outcome=skipped_blocked`). 우회(UA 위장, 프록시, 헤드리스 브라우저)는 하지 않는다. 연속 3회 실행이 차단되면 어댑터를 자동 비활성화하고 관리자에게 알린다.

**요청 예절**
- User-Agent에 서비스명과 연락 수단을 밝힌다. 예: `JapanFindsCollector/0.1 (+https://<서비스 도메인>/bot; contact: <운영 메일>)`
- 요청 간격: Yahoo! 쇼핑은 문서의 "1クエリー/秒"보다 느리게(초기값 1.5초 이상). RSS는 실행당 피드별 1회.
- 조건부 요청(`If-Modified-Since`, `ETag`)을 써서 변경이 없으면 본문을 받지 않는다(PR TIMES가 지원하는지는 확인 필요).
- 실행당 소스별 요청 상한을 설정값으로 둔다(초기값 예: Yahoo! 200건). 한도에 한참 못 미치는 수준으로 운영한다.
- robots.txt는 매 실행 전에 다시 읽고, Disallow가 생기면 그 경로를 수집하지 않는다.
- 약관 · robots 재확인을 분기 1회 운영 체크리스트에 넣는다.

## 4. LLM 분석 출력 스키마와 프롬프트 설계

### 4.1 출력 JSON 스키마 (초안)

```json
{
  "schema_version": "0.1",
  "candidate_id": "string",
  "is_product_announcement": { "value": true, "confidence": 0.0 },
  "fields": {
    "name_ko":        { "value": "string|null", "confidence": 0.0, "evidence": [], "status": "ok|needs_check|not_found" },
    "name_ja":        { "value": "string|null", "confidence": 0.0, "evidence": [], "status": "ok" },
    "summary_ko":     { "value": "string|null", "confidence": 0.0, "evidence": [], "status": "ok" },
    "brand":          { "value": "string|null", "confidence": 0.0, "evidence": [], "status": "ok" },
    "category":       { "value": "character_goods|food|beauty|fashion|toy|stationery|etc|null", "confidence": 0.0, "evidence": [], "status": "ok" },
    "limited_type":   { "value": "period|quantity|region|store|collab|preorder|none|unknown", "confidence": 0.0, "evidence": [], "status": "ok" },
    "release_date":   { "value": "YYYY-MM-DD|null", "precision": "day|month|season|unknown", "confidence": 0.0, "evidence": [], "status": "ok" },
    "end_date":       { "value": "YYYY-MM-DD|null", "precision": "day|month|while_supplies_last|unknown", "confidence": 0.0, "evidence": [], "status": "ok" },
    "sales_channels": { "value": [ { "name": "string", "url": "string|null", "type": "online|store|both|unknown" } ], "confidence": 0.0, "evidence": [], "status": "ok" },
    "price":          { "value": { "amount": 0, "currency": "JPY", "tax_included": true }, "confidence": 0.0, "evidence": [], "status": "ok" },
    "jan_code":       { "value": "string|null", "confidence": 0.0, "evidence": [], "status": "ok" }
  },
  "duplicate_candidates": [
    { "target_id": "string", "reason": "string", "confidence": 0.0 }
  ],
  "review_flags": ["string"],
  "notes_for_admin_ko": "string"
}
```

`evidence` 배열의 한 항목:

```json
{ "source_field": "title|description|api_field", "quote": "원문에서 그대로 옮긴 짧은 구절", "char_start": 0, "char_end": 0 }
```

- `quote`는 **입력 텍스트에 실제로 있는 문자열**이어야 한다. 서버가 `input[char_start:char_end] == quote`를 검증하고, 맞지 않으면 그 필드를 `needs_check`으로 낮춘다.
- `quote`는 근거 확인용 짧은 구절이다. 관리자 화면에만 보이고 사용자 화면에는 노출하지 않는다.
- `confidence`는 0~1. 임계값(초기값 예: 0.7) 미만이거나 `evidence`가 비면 관리자 화면에 "확인 필요"로 표시한다.
- 값이 원문에 없으면 `value=null`, `status=not_found`. **추측해서 채우지 않는다.**
- `tax_included`를 알 수 없으면 null로 두고 `status=needs_check`.

### 4.2 프롬프트 설계 요점

1. **입력은 데이터, 지시가 아니다.** 수집한 제목 · 요약을 구분 태그 안에 넣고, 그 안의 문장이 지시처럼 보여도 따르지 않게 시스템 프롬프트에 명시한다(보도자료 · 상품 설명에 숨은 문구가 들어올 수 있음).
2. **추출 우선, 생성 최소.** 상품명 · 가격 · 날짜 · 판매처는 원문에 있는 것만 옮긴다. 한국어 요약은 사실만 2~3문장으로 새로 쓰고, 원문 문장을 번역해 길게 이어 붙이지 않는다(본문 복제 방지).
3. **불확실하면 "확인 필요".** 날짜가 "11월 중순", "순차 발매"처럼 모호하면 `precision`으로 표현하고 `value`를 억지로 만들지 않는다. 연도가 없으면 발행일을 기준으로 추정하되 `needs_check`으로 표시한다.
4. **근거 인용 필수.** 모든 필드에 `evidence`를 요구하고, 근거가 없으면 `not_found`로 두게 한다.
5. **고유명사 처리.** 한국어 상품명은 공식 한국어 표기가 있는 캐릭터 · 브랜드명만 그 표기를 쓰고, 불확실하면 일본어 원문을 병기한 뒤 `needs_check`.
6. **한정 유형은 닫힌 목록.** 4.1의 enum에서만 고르게 하고, 근거 문구(期間限定, 数量限定, 店舗限定, 受注生産 등)를 인용하게 한다.
7. **상품 발표가 아닌 글 걸러내기.** 인사 · 실적 · 이벤트 공지 등은 `is_product_announcement=false`로 표시해 검수 대기열에 올리지 않는다.
8. **중복 판별은 후보 제시까지.** 서버가 미리 좁힌 유사 후보 목록(브랜드 · 발매일 근접)을 함께 주고, 같은 상품인지와 이유를 답하게 한다. 병합은 관리자가 한다.
9. **구조화 출력.** JSON 스키마를 강제하고, 스키마 검증에 실패하면 1회만 재요청한 뒤 `needs_review`로 넘긴다.
10. **재현성.** `llm_model`, `llm_prompt_version`을 candidate에 기록한다.
11. **소스별 제외.** 가샤폰 사이트처럼 AI 2차 이용을 금지한 소스의 본문은 LLM 입력에 넣지 않는다(수동 등록 건은 관리자가 쓴 텍스트만 다룸).

## 5. 이미지 · 저작권 처리 방침

확인된 범위 안에서 정한 기본값이다. 법률 자문을 대신하지 않는다.

**공통 기본값**
- 이미지 파일을 내려받아 자체 서버 · 스토리지에 저장하지 않는다.
- 본문 전문을 저장 · 게시하지 않는다. 게시하는 것은 자체 작성 한국어 요약 + 사실 필드 + 출처 링크다.
- 모든 상품 카드에 출처(소스명, 원문 링크, 확인일)를 표시한다.
- 권리자의 삭제 요청 창구를 서비스에 두고, 요청이 오면 즉시 비공개 처리한다.

**소스별**

| 소스 | 이미지 방침 | 근거 |
|---|---|---|
| PR TIMES | **이미지 게시 안 함(기본값).** 원문 링크만. 이미지를 쓰려면 (a) 보도자료를 낸 기업의 개별 허락, 또는 (b) 미디어 유저로 등록해 보도 목적 이용 조건을 충족 — 둘 중 하나를 확인한 뒤 | [확인] 일반규약 제3조 · 제6조(사적 복제 · 인용 범위만), 보도규약 제3조(보도 목적 한정), 기본규약 제14조(저작권은 기업 귀속). robots.txt가 `releaseimage` 경로를 Disallow |
| 포켓몬센터 온라인 | 이미지 사용 안 함. 텍스트 카드 + 공식 페이지 링크 | [확인] 약관 제5조(개인적으로 즐기는 범위의 이용 허락), 제6조 ④⑥ |
| 치이카와 마켓 | 이미지 사용 안 함(핫링크 포함). 텍스트 카드 + 공식 페이지 링크 | [확인] 【著作権等について】 사적 이용을 넘는 복제 · 공표 금지 |
| 반다이 가샤폰 | 이미지 · 문장 · 데이터 전재 안 함. 관리자가 사실만 자기 문장으로 입력 | [확인] 사이트 이용 조건의 무단 전용 · 전재 금지, AI 2차 이용 금지 |
| 라쿠텐 | **확인 못함** — 방침 미정 | 공식 규약 503 |
| Yahoo! 쇼핑 | API가 돌려준 이미지 URL을 **그대로 참조해 표시**하는 것을 잠정 기본값으로 하되(저장 · 가공 안 함), 크레딧 표시와 상품 페이지 링크를 함께 둔다. 조건 확인 전에는 텍스트 카드로 출시 가능 | [확인] API가 `hits/image/*` URL을 제공, 크레딧 표시 의무. [확인 필요] 이미지 URL 사용 · 보관 조건은 확인한 페이지에 기재 없음 |

**"인용"으로 처리하려는 경우** — 일본 저작권법상 인용 요건(주종 관계, 명료 구분, 출처 명시, 필요 최소한 등)을 충족해야 하고, 한국 사용자 대상 서비스에서 어느 나라 법이 적용되는지도 따져야 한다. 이 문서는 그 판단을 하지 않는다 → **[확인 필요] 법률 검토.**

**이미지 없는 카드 디자인** — 위 방침상 MVP의 다수 카드가 이미지 없이 나간다. 브랜드 컬러 · 카테고리 아이콘 · 한정 유형 배지로 구성한 텍스트 카드를 기본형으로 설계한다.

### 미결 사항 (확인 필요 목록)

1. **라쿠텐 웹서비스 전체** — 엔드포인트 · 버전, 신청 조건, 호출 한도, 크레딧 표기, 응답 필드, 데이터 · 이미지 이용 조건. (공식 사이트 503으로 확인 못함. 2026-05 API 이전설은 제3자 글에서만 봄)
2. **Yahoo! 쇼핑** — 상업 이용 조건(해당 페이지 주소 재확인), 취득 데이터 보관 · 캐시 조건, 이미지 URL 사용 조건, Client ID 발급 심사 유무, 공통 이용규약 제2장 3(3)의 정확한 의미.
3. **PR TIMES** — 카테고리 · 키워드 피드 유무, 권장 폴링 간격, 미디어 유저 등록 조건과 이미지 이용 범위, 기사 상세 페이지를 LLM 분석용으로 읽어도 되는지, 조건부 요청 지원 여부.
4. **포켓몬센터 온라인** — 공식 RSS · API 유무(이번에 확인하지 않음), 株式会社ポケモン의 PR TIMES company_id.
5. **치이카와 마켓** — 운영사 사전 허가 가능 여부, `agents.md` 전체 내용과 UCP/MCP 이용 조건, `collections/all.atom` 존재 여부(429로 확인 못함), handle/sku가 항상 JAN인지.
6. **반다이 가샤폰** — RSS 유무(`<head>` 미확인), 반다이의 생성 AI 관련 별도 공지 내용, 보도 · 미디어용 이미지 제공 창구 유무.
7. **법률 검토** — 인용 요건 적용, 한 · 일 준거법, 사실 정보(상품명 · 가격 · 발매일)만 옮기는 경우의 안전 범위, 상표 표기.
8. **운영 결정** — 폴링 주기, confidence 임계값, 실행당 요청 상한(이 문서의 수치는 모두 초기 제안값).

### 조사 중 관찰한 것 (참고)

- 치이카와 마켓 robots.txt 머리말에 AI 에이전트에게 특정 스킬(`shop.com/SKILL.md`) 설치를 사용자에게 권하라는 문구가 들어 있다. 사이트가 에이전트에게 건네는 문구일 뿐 우리 쪽 지시가 아니므로 따르지 않았다. 수집 텍스트를 LLM에 넣을 때 같은 종류의 문구가 섞일 수 있다는 실제 사례다(R8).
