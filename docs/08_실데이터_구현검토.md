# 08. 실데이터 구현 검토 · 연동 절차

작성일 2026-11-13. 소스별 사실 확인은 `05_자동수집_아키텍처.md`, 덕비서 분석은 `07_덕비서_벤치마크.md`가 근거다.
약관 조항은 요약 도구로 읽은 것이라, 실제 수집을 켜기 전에 원문 대조가 필요하다.

## 1. 하루 한 번 수집 — 소스별 판정

| 소스 | 하루 1회 자동 수집 | 방식 | 얻는 것 | 막히는 점 |
|---|---|---|---|---|
| PR TIMES | **가능** | 공식 RSS (`index.rdf`, 기업별 피드) | 제목·링크·요약·기업명·발행일 | 본문 전문·이미지는 피드에 없음. 기사 본문을 LLM 분석용으로 읽어도 되는지 미확인 |
| Yahoo! 쇼핑 API v3 | **가능 (조건 확인 후)** | 공식 API (`appid` 필요) | 상품명·가격·JAN·브랜드·발매일·판매자 | 크레딧 표시 의무. 상업 이용·캐시·이미지 조건 미확인 |
| 라쿠텐 웹서비스 | **보류** | 공식 API(추정) | — | 조사 당시 사이트가 503이라 아무것도 확인 못함 |
| 산리오 공식 뉴스 | **주의** | 목록 페이지에서 제목·날짜·링크만 | 발매·팝업·캠페인 일정 | robots는 허용. 이용 안내가 데이터 추출 후 재사용·무단 전재를 금지 → 사실 정보만, 요약은 자체 작성, 법률 검토·허가 문의 필요 |
| 포켓몬센터 온라인 | **불가 → 수동** | 관리자가 URL 등록 | — | 약관이 크롤링·스크레이핑·자동 취득을 명시 금지 |
| 치이카와 마켓 | **불가 → 수동** | 관리자가 URL 등록 | — | 약관이 사전 허가 없는 자동 취득 금지 (기술적으로는 `/products.json`이 열려 있으나 쓰지 않음). 허가를 받으면 전환 가능 |
| 반다이 가샤폰 | **불가 → 수동** | 관리자가 URL 등록 | — | 자동 취득·무단 전재·AI 2차 이용 금지 → LLM 분석에도 넣지 않음 |

정리: **지금 바로 매일 자동으로 돌릴 수 있는 것은 PR TIMES RSS 하나, 키만 받으면 Yahoo! 쇼핑 API까지 둘.**
캐릭터 공식몰 3곳은 자동 수집 대신 "관리자 URL 등록 → 사람이 확인"으로 가야 하고, 덕비서처럼 넓게 모으려면 운영사 허가 요청이 선행돼야 한다.

## 2. 지금 화면의 콘텐츠를 실데이터로 채울 수 있는가

| 화면 요소 | 실데이터 가능 여부 | 채우는 방법 | 남는 문제 |
|---|---|---|---|
| 상품명(일본어)·브랜드·출시일 | 가능 | PR TIMES 제목·요약 + LLM 추출 → 관리자 승인 | 요약만으로 부족하면 '확인 필요'로 남음 |
| 한국어 상품명·요약 | 가능 | LLM 번역·요약 → 관리자 수정 | LLM 비용·모델 결정 필요 |
| 한정 유형·근거 | 부분 가능 | 제목의 限定 키워드로 후보 → 관리자가 원문에서 근거 확인 | 자동 판정만으로 게시하지 않음 |
| 일본 가격 | 부분 가능 | Yahoo API(유통 상품) / 보도자료 가격(관리자 입력) | 매장·팝업 한정품은 API에 없음 → 수동 |
| 한국 가격·가격 비교 | **미확보** | 한국 가격 소스를 아직 검토하지 않음(네이버 쇼핑 API 등 후보) | 같은 상품 확인은 사람이 해야 함. 초기에는 소수만 수동 |
| 원화 환산 | **미확보** | 환율 API 선정 필요 | 지금은 데모용 가정 환율 |
| 판매처·지역·구매 조건 | 부분 가능 | LLM 추출 + 관리자 확인 | — |
| 일정(팝업·발매·응모) | 부분 가능 | PR TIMES + 수동 등록. 산리오 뉴스는 검토 통과 시 | 종료·변경 추적은 링크 재확인 작업 필요 |
| 상품 이미지 | **미확보** | 사용권 확인된 이미지만. 그 전까지 자체 일러스트 | 가장 큰 공백. 보도자료 이미지 이용 범위 미확인 |
| 에디터 추천·최근 등록 | 가능 | 관리자 지정·등록일 | — |
| 인기순·'인기' 표기 | 출시 후 | 실제 조회·저장 데이터가 쌓인 뒤 | 그 전에는 노출하지 않음 |
| 관심 상품 | 가능 | 지금은 브라우저 저장 → Supabase Auth | — |
| 구매 부탁 전환 | 겸사겸사 준비 시 | 환경변수에 부탁 작성 주소 입력 | 겸사겸사 쪽 수신 규격 필요 |

결론: 화면 구조는 그대로 실서비스로 갈 수 있다. 다만 **이미지, 한국 가격, 환율** 세 가지는 소스가 정해지지 않았고,
**캐릭터 공식몰 상품**은 자동이 아니라 사람 손이 들어간다. 초기 운영은 "매일 자동 후보 수집(PR TIMES) + 관리자 하루 검수 + 인기 캐릭터는 수동 등록"이 현실적이다.

## 3. 매일 1회 실행 구조

```
GitHub Actions (schedule: 하루 1회)
  └─ Python 수집기
       ├─ PR TIMES RSS 읽기 → 키워드(限定·ポップアップ·コラボ …) 필터
       ├─ (키 발급 후) Yahoo API로 게시 상품 가격 재확인
       ├─ 수동 등록 URL 링크 생존 확인
       └─ Supabase product_candidates · collection_logs 에 기록 (실패 시 지수 백오프 재시도)
  └─ LLM 분석 → 후보에 한국어 이름·분류·confidence 저장
관리자 /admin 에서 승인 → products 게시 → 사이트 반영
```

비밀값은 GitHub 저장소 Secrets에 둔다: `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, LLM API 키, `YAHOO_JP_CLIENT_ID`.

## 4. Supabase · Vercel 연동 절차

1. **Supabase 스키마**: 대시보드 → SQL Editor에 `supabase/schema.sql`을 붙여 실행. (아직 실행 검증 전이라 오류가 나면 그 메시지를 기준으로 고친다.)
2. **Vercel 프로젝트**: vercel.com → Add New → Project → GitHub 저장소 `KimJin-Ian/japan` Import. Framework는 Next.js로 자동 인식.
3. **Vercel 환경변수** (Project → Settings → Environment Variables):
   - `NEXT_PUBLIC_SITE_URL` = 배포 주소
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
   - `SUPABASE_SECRET_KEY` (Sensitive로 표시)
   - `ADMIN_USER`, `ADMIN_PASSWORD` (없으면 배포 환경에서 `/admin`은 404)
   - `NEXT_PUBLIC_GYEOMSA_REQUEST_URL` (겸사겸사 준비되면)
4. **더 쉬운 방법**: Vercel → Integrations → Supabase를 연결하면 Supabase 키가 Vercel 환경변수로 자동 들어간다.
5. 이후 `main`에 푸시할 때마다 Vercel이 자동 배포한다.

## 5. 먼저 정해야 할 것

1. 채팅에 올렸던 Supabase Secret key와 GitHub 토큰 폐기·재발급
2. GitHub 저장소 공개 범위 (현재 PUBLIC — 기획 문서가 함께 공개됨)
3. LLM 제공사·모델과 월 예산
4. 이미지 정책 (자체 일러스트 유지 / 보도자료 이미지 / 운영사 허가)
5. 한국 가격 소스와 환율 소스
6. 캐릭터 공식몰 운영사에 수집 허가를 문의할지
